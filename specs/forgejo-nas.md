# First NAS Forgejo pilot

Before building, provision `forgejo/oidc-client-secret` (a new, random, single-line client secret; e.g. 32 random bytes encoded as hex) and `forgejo/authentik-username` (exact existing Authentik username, not display name) in the NAS SOPS file and update the `sopsSecrets` input. Do not paste values in logs/chat or reuse the Headscale secret. Missing credentials can prevent the shared Authentik worker from starting. Reserve `forgejo-recovery` for local recovery; use a different OIDC username and email.

Keep a working admin session open. Confirm no existing Authentik application/provider uses slug `forgejo`, name `Forgejo` or client ID `nas-forgejo`; the default provider consent/invalidation flows and `authentik Self-signed Certificate` should exist. No manual provider creation, Headscale change or global passkey flow change is needed. Review unrelated worktree changes before deploying the NAS configuration. Build first, then activate with the normal NAS workflow. Expect the Authentik services to reload. The extra CLI build lets the admin command read its secret without putting it in process arguments.

## Acceptance after activation

- Check `systemctl status forgejo authentik-worker` and the Authentik blueprint instance **NAS - Forgejo OIDC**. It must report successful application. If startup raced discovery, confirm the blueprint succeeded before retrying `forgejo.service`. On credential rotation explicitly reapply the blueprint: restarting the worker alone does not change the blueprint file hash.
- From a tailnet client, open `https://git.bepis.lol`, use **authentik**, and complete the existing passkey flow. Verify an ordinary second identity cannot obtain access and unauthenticated visitors cannot read or register. From off-tailnet confirm the public NAS ingress cannot serve this hostname even when its address is supplied explicitly.
- On NAS, privately retrieve `/var/lib/forgejo/initial-recovery-login` as root; it contains a generated initial password. Log in as `forgejo-recovery` in a separate browser, change the password, store it in your password manager and remove the initial receipt. Startup does not reset an existing recovery password. Do not send the receipt to an agent or terminal recording.
- Create a disposable private repository. Use a repo-scoped Forgejo token via a credential helper for HTTPS Git, not an Authentik password. Push a branch and a small LFS object and clone them in a fresh checkout. Test a PR. No SSH Git, runner or deployment credentials are configured. The shared proxy limits individual uploads to 200 MiB.
- Verify a fresh Headscale login without signing out of the existing session. A Nix rollback does not revert database state, blueprint objects or Forgejo migrations. Keep important repositories canonical elsewhere until backups have been addressed.
