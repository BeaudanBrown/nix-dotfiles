# Patch OnePlus bottom-mic ASoC/ADSP exact-zero capture

Kernel-development follow-up split from nd-hr89. Existing userspace trials show the bottom-mic route opens and the ALSA PCM reaches RUNNING with advancing pointers, but samples remain exact-zero on current generation 74/75 state. The remaining work is not a Nix/UCM/PipeWire change: instrument or patch the Qualcomm ASoC/ADSP path for hw:O6T,1 / MultiMedia2 -> SLIMBUS_0_TX -> AIF1_CAP -> SLIM TX0 -> CDC_IF TX0 -> DEC0 -> ADC4/AMIC4 on sdm845/wcd934x/q6afe/slim.

## Design

Do this only in an explicit kernel-development flow, not normal /aloop. Start from trial records docs/oneplus-audio-trials/20260614T135658Z-gen70-speaker-only-ucm-retrace.md (non-zero) and docs/oneplus-audio-trials/20260615T144115Z-nd-hr89-current-kernel-boundary.md (current exact-zero). Candidate seams: q6afe port/channel-map/programming for SLIMBUS_0_TX/MultiMedia2, wcd934x ADC4/DEC0/CDC_IF TX0 power-up and reset state, and SLIM NGD runtime state after boot. Keep speaker-only UCM and avoid static PipeWire sources.

## Acceptance Criteria

A kernel/device-tree/ADSP-side patch or trace explains the exact-zero state and either restores non-zero bottom-mic capture without regressing speaker playback, or identifies the exact upstream subsystem/patch target with enough trace evidence for upstream/mainline work.
